# PJM-инструменты для техники

## sbw_vehicle_tools.js — плагин Blockbench (хитбоксы и точки)

Установка: Blockbench → **File → Plugins → (⋮) Load Plugin from File** → выбрать
`pjm-tools/sbw_vehicle_tools.js`. Появятся два пункта в меню **Tools**.

**Хитбоксы (OBB):**
1. Рисуй кубы-хитбоксы поверх модели где угодно.
2. Выдели куб(ы) → **Tools → «SBW: назначить хитбокс»** → выбери тип в диалоге —
   кубы сами переименуются и переедут в группу `obb` (или `obb_turret`, если
   отметить «бокс башни» — такие крутятся с башней). Пункт «Гусеница — авто
   лево/право» сам решит `WheelLeft`/`WheelRight` по стороне куба: можно выделить
   оба трака сразу.
3. **Tools → «SBW: экспорт OBB»** — готовая секция `"OBB": [...]` в буфере обмена,
   вставляй в `data/superbwarfare/sbw/vehicles/<машина>.json`.
4. Куб можно вращать (пивот держи в центре куба!) — наклон уедет в `CustomRotate`.
5. Группы `obb`/`obb_turret` создаются с выключенным **Export** — в geo.json модели
   боксы не попадут. Если создавал группы руками — выключи Export сам (ПКМ по группе).

**Точки (камеры, ShootPos, сиденья):**
выдели куб-маркер → **Tools → «SBW: координаты точки»** — в буфере абсолютные
координаты + относительно `turret` / `barrel` / станции. Берётся **центр** куба.

Проверка после установки: выдели любой куб с известными координатами (например,
на станции) и сверь строку «отн. turret» с текущими значениями в JSON — числа
должны совпасть.

Развёрнутый root (`rotation [0,180,0]`) плагин определяет и учитывает сам.


Скрипты для работы с SBM-моделями техники (Python 3, зависимостей нет).
Оба понимают модели, у которых root развёрнут на 180° (`rotation: [0, 180, 0]`),
и обычные модели в конвенции SBW (перёд = −Z).

## vehicle_coords.py — координаты для data-JSON

Переводит координаты Blockbench в data-пространство SBW (блоки; X влево, Y вверх, Z вперёд).

```bash
# пивоты ключевых костей + габариты модели в data-координатах
python3 pjm-tools/vehicle_coords.py <geo.json> info

# точка (например, положение глаза камеры) — абсолютно ("Transform": "Vehicle")
python3 pjm-tools/vehicle_coords.py <geo.json> point X Y Z

# та же точка относительно кости — для "Transform": "Turret" / ShootPos ("Barrel") /
# станции ("WeaponStation" = passengerWeaponStationYaw)
python3 pjm-tools/vehicle_coords.py <geo.json> point X Y Z --rel turret

# OBB-хитбокс по двум противоположным углам бокса в Blockbench -> "Size" + "Position"
python3 pjm-tools/vehicle_coords.py <geo.json> obb X1 Y1 Z1 X2 Y2 Z2
```

Рабочий процесс: в Blockbench поставь временный кубик в нужную точку (глаз камеры,
дуло, угол хитбокса), сними его координаты, прогони через скрипт, кубик удали.

## track_path_gen.py — натяжка гусениц

Строит контур гусеницы по каткам (внешние касательные + дуги) и печатает готовый
Kotlin-блок `TRACK_T/Y/Z/ROT` + `getTrackDistance` / `getTrackAnimationLength`
для рендерера на `SbmVehicleRenderer` (образец использования таблиц — `M10BookerRenderer`).

```bash
python3 pjm-tools/track_path_gen.py <geo.json> \
    --idler wheelL0:5.11 \
    --sprocket wheelL7:4.78 \
    --road wheelL1,wheelL2,wheelL3,wheelL4,wheelL5,wheelL6:7.33 \
    --rollers small_wheelL0,small_wheelL1,small_wheelL2:2.62 \
    --rest trackMovL0 --links 91
```

- Радиус после `:` — это радиус катка **плюс** полтолщины звена. Если не указывать,
  посчитается из кубов кости (грубо) + `--link-thickness/2`.
- `--rest` — кость звена (`trackMov*`); её пивот должен лежать на контуре
  **у верха звёздочки** (там обычно моделлер оставляет стопку звеньев).
- `--links` — число звеньев на борт (сколько костей `trackMov*` на сторону).
- Требования к модели: звенья называются `trackMov<L|R><n>` с дочерней
  `trackRot<L|R><n>`, все с одинаковым пивотом; катки — `wheel<L|R><n>`.

Проверка: запуск с параметрами выше воспроизводит таблицы M10 Booker один в один.

## ka52_model_fixup.py — привязка модели Ка-52

Запускать после **каждой** замены `ka_52.geo.json` из Blockbench:

```bash
python3 pjm-tools/ka52_model_fixup.py
```

Скрипт идемпотентный, делает три вещи: ставит `identifier`, чинит пивот прицельного
контейнера `pricel` (в модели он зеркальный по Z — вокруг такого нельзя вращать) и
поднимает геометрию так, чтобы **самая нижняя точка отрисовки легла на y = 0**.

Последнее важно: нижняя грань ванильного AABB сущности совпадает с началом координат
модели, поэтому машина садится на неё, а всё, что смоделировано ниже нуля, уходит в
грунт. У Ка-52 так висели стойки шасси (−0.216 бл). Для сравнения: у Ми-28 низ модели
на −0.031 бл, у Т-90А на −0.015 — апстрим держит этот ноль. `Collision`-OBB на просадку
не помогает: при установленном Create: Aeronautics `VehicleEntity.move()` уходит в
ванильный `super.move()` и OBB-коллизия не используется вовсе.

Если скрипт впервые поднял модель на N единиц (печатает в консоль), все Y в
`data/superbwarfare/sbw/vehicles/ka_52.json` — OBB, кресла, камеры, `TurretPos`,
`ShootPos` в системе `Vehicle`, `TerrainCompat`, `RotateOffsetHeight` — надо сдвинуть
на те же N/16 блока. При обычном ре-экспорте той же модели подъём выходит нулевой.
